# DisclosureOS 2.0.0-beta.1 candidate

This coordinated beta candidate makes C1 available for integration testing:
sourced event and setting context, precise claim subjects, and review of exact
caller-supplied document snapshots. All seven packages advance to
`2.0.0-beta.1` with the `beta` tag. This document is release preparation, not a
publication receipt. npm `latest` remains on the existing stable releases.

## What changes

- Records adds Observation context 0.1.0 and Claim history 0.2.0 through explicit
  experimental exports. Event, reported-object, place, platform, environment,
  temporal and collection entities preserve attributed assertions, missingness,
  original wording and links to existing measurements.
- Schema adds `evaluateContextClaimHistory`, checking exact supplied snapshot
  bytes and references without fetching. Source-artifact authenticity, temporal
  normalization, profile validation, scientific interpretation and sensor fusion
  are explicitly outside its successful result.
- Observables, origins, instruments, scoring and CLI advance with the coordinated
  dependency set. Their scientific definitions and existing contracts do not
  change in this packaging checkpoint.

Implementation baseline: `9e7c76ad8421d2a5a76fa1e6aae15b184cc8de3d` (merged C1).
Existing schema identities remain immutable, including Claim history 0.1.0.
The unversioned claim schema export continues to identify 0.1.0; consumers choose
the new 0.2.0 export explicitly. No schema bytes change during packaging.

```ts
import {
  parseObservationContext,
  parseContextClaimHistory,
} from '@disclosureos/records/experimental/v2';
import {
  evaluateContextClaimHistory,
} from '@disclosureos/schema/experimental/v2';
```

See the [C1 guide](../c1/README.md), its [field ledger](../c1/baseline-mapping.csv)
and the [fictional multi-sensor example](../../examples/v2/context-demo/README.md).
The ledger accounts for 152 baseline occurrences assigned to C1. It is not a
claim that the remaining research domains, C2 and C3, are complete.

## Release acceptance

Follow the [release process](../release-process.md) using Node 22 and pnpm 9.15.0.
The changeset has already been applied: do not rerun versioning to publish this
candidate. Check the complete package and conformance suite, then commit the
reviewed release inputs before creating tarballs:

```sh
pnpm install --frozen-lockfile
pnpm --filter '@disclosureos/*' build
pnpm --filter '@disclosureos/*' type-check
pnpm --filter '@disclosureos/*' test run
pnpm --filter '@disclosureos/*' lint:publish
node --test conformance/*.test.mjs scripts/audit-partner-window.test.mjs scripts/partner/map-eldaeon-intake.test.mjs
pnpm conformance:baseline
pnpm conformance:matrix
pnpm test:release
pnpm release:check
pnpm release:pack /tmp/disclosureos-beta1-candidate
```

Use a new output directory. `release:pack` installs all seven packed artifacts in
an independent npm consumer, checks every export and schema, type-checks NodeNext
and Bundler imports, runs the Observation/claim corpus and CLI migration acceptance,
and now runs C1 from that installed package set. Its C1 checks include:

- parsing context and selecting Claim history 0.2.0 explicitly;
- successful exact-snapshot review, preserved conflicts and unknown alignment;
- failure for missing snapshots or changed bytes under a declared digest;
- input preservation and explicit boundaries on unchecked scientific results;
- execution of the committed fictional example from outside the workspace.

The manifest records `contextSnapshotConsumer: passed` only after the independent
consumer succeeds. Registry publication must use the verified tarballs and retain
their hashes; software acceptance is not a scientific certification.

## Publication and public portal

After release review and merge, regenerate the candidate at the exact merged
commit and verify registry availability, then publish using the authorized beta
procedure. Record all seven registry integrities, beta tags and unchanged latest
tags. A merge alone does not publish a version.

Once registry verification passes, the portal can pin beta.1, replace its
review-only C1 copies with published package imports and expose
`/v2/records/context` with matching Records, Claims and documentation navigation.
Until then `/pilot/context` remains a local/preview reference. The public ELDÆON
viewer remains a partner preview; none of the C1 control data comes from ELDÆON.
