# DisclosureOS 2.0.0-beta.2 candidate

This coordinated beta candidate adds C2a: detailed witnesses and accounts, sourced
qualifications and procedures, and entity-addressed reviewer interpretations.
All seven packages advance to `2.0.0-beta.2` under `beta`. This document prepares a
release; it is not a publication receipt. npm `latest` remains on stable v1.

## Package changes

- Records adds research-entities 0.1.0 and claim-history 0.3.0 through explicit
  experimental exports. Public witnesses, distinct accounts, polygraph procedures
  and aggregate witness declarations retain source attribution and missingness.
  Qualifications include their relevant time. Claims can address an exact entity,
  field and source assertion. Credibility vocabulary remains attributable to a
  reviewer, with no automatic score or independence inference.
- Schema adds `evaluateResearchClaimHistory`, checking exact supplied snapshot
  bytes, observation scope, typed references and history dependencies. It does
  not fetch source artifacts, authenticate testimony or certify an interpretation.
- Observables, origins, instruments, scoring and CLI advance with the coordinated
  dependency set. Their scientific definitions and existing contracts do not change.

Implementation baseline: `25d01be3b8cf08d76acdbac7170063936e8af49f` (merged PR #53).
All previously committed schema bytes are immutable, including both C1 contracts.
The unversioned claim schema export still selects 0.1.0; the new 0.3.0 parser and
schema export are chosen explicitly. Existing profiles do not silently accept it.

```ts
import {
  parseResearchEntities,
  parseResearchClaimHistory,
} from '@disclosureos/records/experimental/v2';
import { evaluateResearchClaimHistory } from '@disclosureos/schema/experimental/v2';
```

See the [C2a guide](../c2/README.md), [field ledger](../c2/witness-baseline-mapping.csv)
and [fictional historical-account example](../../examples/v2/witness-accounts-demo/README.md).
One witness has two accounts; an event quarter and recording year retain their
precision. Unknown oath, consent, polygraph and independence remain unknown.
None of this example is ELDÆON data or an actual historical case.

## Release acceptance

Use Node 22 and pnpm 9.15.0 following the [release process](../release-process.md).
Versioning has already been applied. Do not run it again merely to publish.

```sh
pnpm install --frozen-lockfile
pnpm --filter '@disclosureos/*' build
pnpm --filter '@disclosureos/*' type-check
pnpm --filter '@disclosureos/*' test run
pnpm --filter '@disclosureos/*' lint:publish
node --test conformance/*.test.mjs scripts/audit-partner-window.test.mjs scripts/partner/map-eldaeon-intake.test.mjs
pnpm conformance:baseline
pnpm conformance:matrix
python3 scripts/check-c1-mapping.py
python3 scripts/check-c2-witness-mapping.py
pnpm test:release
pnpm release:check
pnpm release:pack /tmp/disclosureos-beta2-candidate
```

Pack from the clean, committed candidate into a new directory. The isolated npm
consumer checks all exports, exact schema bytes, NodeNext/Bundler types, the
Observation/claim corpus, CLI migration acceptance and both C1 and C2a examples.
C2a includes successful snapshot resolution, rejection of missing/tampered bytes
and explicit rejection by older history dispatch. The manifest records
`witnessAccountsConsumer: passed` only after these checks succeed.

## Publication and portal

After review and merge, regenerate at the exact merged release commit. Inspect
registry availability and existing tags, publish the verified tarballs under
`beta`, and compare retrieved bytes with the candidate manifest. Retain unchanged
`latest` tags. A merge alone does not publish packages.

Only after registry verification should the portal pin beta.2 and replace its
review copies with package imports. The planned public witness/account reference
will align field exploration, the worked example, documentation and explicit
0.3.0 inspector dispatch. Existing testimony provenance profiles remain separate
from the new entity-snapshot checks.

C2a accounts for 61 witness/testimony field occurrences: 51 reorganized and ten
source-document metadata fields assigned to C2b. Document editions/digital
provenance, materials/analysis and C3 application publication controls remain later
checkpoints. Public shapes reject private identity-map/contact properties but are
not a privacy sanitizer. Source-artifact authenticity, scientific interpretation,
profile applicability and private-data access control are not certified here.
