# DisclosureOS 2.0.0-beta.6

Security maintenance release for the seven coordinated foundation packages.
Publication is authorized after final verification; registry publication is not
complete until a registry receipt is recorded here. Stable V1 `latest` tags stay
unchanged.

## Changes

All package dependencies use Zod 4.6.6, which fixes
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
New installations of this release do not require the Beta 5 Zod override.
Oversized constrained arrays, sets and maps are rejected before their members
are parsed. Applications must still impose appropriate limits on untrusted input.

The data contracts, source mappings and integration scope remain those of
[Beta 5](2.0.0-beta.5.md). Published schema files, identifiers and hashes remain
unchanged. A plain-data emission helper preserves the existing equivalent
nullable, fixed-tuple and timestamp representations when generating schemas
with the newer dependency. Existing drift and published-identity gates remain
active.

The repository-only CSV example reader also uses patched `csv-parse` 7.0.2
for GHSA-8cw4-87c7-c6xx. This dependency is not shipped in the seven packages.

## Compatibility note

Qualified timestamps must include seconds, such as `2026-11-15T12:00:00Z`.
The previous Zod runtime accepted minute-only values in some date-time fields,
even though the published JSON Schema `date-time` format already required
seconds. Beta 6 consistently rejects those values. This does not justify adding
invented seconds to an uncertain capture time: use the appropriate time precision
or unknown-time representation. Valid timestamp strings are preserved verbatim.

## Verification

The release requires package tests and type checks, the full conformance corpus,
published schema identity checks, and an isolated installation of all seven packed
artifacts. Regression tests cover early rejection of oversized collections,
representation preservation and qualified timestamp validation. The portal and
its guide examples must pass against the same candidate artifacts before
publication, followed by registry integrity and independent-install checks.

No provider data is added to npm. ELDÆON licensing and Speculor/Sky360 public
access boundaries remain unchanged.
