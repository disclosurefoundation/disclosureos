# DisclosureOS 2.0.0-beta.4 candidate

Status: versioned candidate, not published. Prepared 2026-10-16.
Merges and npm publication remain on hold. All seven packages advance together;
`beta` is the intended publication tag and stable v1 `latest` tags stay unchanged.

## Scope

This candidate collects the implementation after beta.3 into one reviewed set:

- Records: physical specimens, preparation lineage, custody, laboratory results,
  connected cases, case assessments, supplemental links and shared vocabulary references.
- Schema: supplied-snapshot evaluation, approved public case projections, numerical
  array/CSV/video source selection, rotating and steered radar, cooperative
  secondary radar, active and passive sonar, lidar point clouds, satellite rasters,
  and vocabulary bindings. Portable schemas and readers ship through package exports.
- Observables: revised characteristic definitions, support terms and a full retained
  catalog. A reported characteristic does not establish a claim outcome or origin.
- Origins: full OCS catalog export with hierarchy, qualifications and attribution.
- Scoring: revised vocabulary consumers plus provider-defined policies, numeric
  grades, ordinal levels, exact input/method references and bounded comparison.
  Competing provider results remain separate; there is no universal score.
- Instruments and CLI: advance with their dependencies for a consistent install.
  Existing acquisition, intake and reproducibility workflows remain available.

This includes direct changes to earlier beta observable definitions, support terms
and enriched-observation/scoring consumers. Treat the beta.4 set as one unit;
do not mix beta.3 packages or assume old beta assessments have identical meaning.
The version bump itself adds no new scientific definitions or runtime behavior.

## Verification

From a clean checkout at the candidate commit, with Node 22 and the pinned pnpm:

```sh
pnpm install --frozen-lockfile
pnpm test:release
pnpm release:check
pnpm release:pack /absolute/new/beta4-candidate
```

Packages Quality also runs the Node 20 foundation matrix, strict publish checks,
conformance, source-profile reproductions and case consumers. Release-mode packing
checks all seven tarballs, exact internal dependencies, export targets and schema
bytes, then exercises a fresh consumer with NodeNext and Bundler type resolution.
Its manifest records the exact candidate source commit and tarball hashes.

The paired documentation PR must pin that exact commit and exercise the current
17 guide examples with these beta.4 tarballs, including expected failures and
recovery. Its retained receipt is a separate acceptance gate. A source-only
manifest or a reused beta.3 receipt does not satisfy beta.4 verification.
