# DisclosureOS 2.0.0-beta.3 candidate

This coordinated beta candidate adds C2b: exact document editions, digital
artifact custody, scoped identifiers and attributable artifact reviews. All seven
packages advance to `2.0.0-beta.3` under `beta`. These are release-preparation
notes, not a publication receipt. npm `latest` remains on stable v1.

## Package changes

- Records adds research-entities 0.2.0 and claim-history 0.4.0 through explicit
  experimental exports. Source editions, document events, digital artifacts,
  custody actions, external identifiers and dated checks retain source
  attribution, scope and missingness. The witness/account kinds remain available.
- Schema adds `evaluateArchivalClaimHistory`. It checks exact supplied snapshots,
  edition citations, declaration consistency, typed references and dependency
  graphs. It does not fetch or authenticate source artifacts, complete custody
  histories or establish scientific conclusions.
- Observables, origins, instruments, scoring and CLI advance together for a
  consistent dependency set. Existing scientific definitions and schema bytes
  do not change during this packaging checkpoint.

Implementation baseline: `4f80b206e78a7b67ad6ea453aa36d65eb3d0c655` (merged PR #55).
All committed schema bytes at that revision, including C2b, are immutable. Existing
parsers and the default claim-schema export retain their stated versions. The
new history explicitly selects entities 0.2.0; older profiles do not silently
accept the new contracts.

```ts
import {
  parseArchivalEntities,
  parseArchivalClaimHistory,
} from '@disclosureos/records/experimental/v2';
import { evaluateArchivalClaimHistory } from '@disclosureos/schema/experimental/v2';
```

Read the [C2b guide](../c2/archival.md), [127-row field ledger](../c2/archival-baseline-mapping.csv)
and [fictional two-edition example](../../examples/v2/archival-editions-demo/README.md).
The example preserves three versus four pages, a release date alongside unknown
declassification, a legacy MD5 declaration for an unavailable original, and an
explicit custody gap. Its named review is inconclusive. It is not ELDÆON data.

## Release acceptance

Use Node 22 and pnpm 9.15.0 following the [release process](../release-process.md).
Versioning has been applied. Do not repeat it merely to publish.

```sh
pnpm install --frozen-lockfile
pnpm --filter '@disclosureos/*' build
pnpm --filter '@disclosureos/*' type-check
pnpm --filter '@disclosureos/*' test run
pnpm --filter '@disclosureos/*' lint:publish
node --test conformance/*.test.mjs scripts/audit-partner-window.test.mjs scripts/partner/map-eldaeon-intake.test.mjs
pnpm conformance:baseline
pnpm conformance:matrix
python3 scripts/check-c1-mapping.py
python3 scripts/check-c2-witness-mapping.py
python3 scripts/check-c2-archival-mapping.py
pnpm test:release
pnpm release:check
pnpm release:pack /tmp/disclosureos-beta3-candidate
```

Pack from the clean, committed candidate into a new directory. The isolated npm
consumer verifies all exports and schema bytes, NodeNext/Bundler types, the
observation/history corpus, CLI migration acceptance and all three domain examples
(C1, C2a and C2b). C2b additionally exercises wrong-edition citations, page bounds,
unavailable/tampered snapshots, retained missingness and old-version rejection.
The manifest records `archivalEditionsConsumer: passed` only after those checks
succeed. Source artifact integrity and scientific interpretation stay unchecked.
